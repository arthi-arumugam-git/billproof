Three ways counters lie, all measured before a line of this was written

Claude Code writes the exact usage object Anthropic billed into every transcript. The numbers are all there. Reading them correctly is the hard part.

+121%

One response is several lines

Claude Code writes one JSONL line per content block, each repeating the full usage. Thinking + text + tool call = counted three times by anything that sums lines. billproof dedupes by message id.

−37.5%

Two cache tiers, two prices

A 5-minute cache write is 1.25x base. A 1-hour write is 2x. More than half of all turns on this machine used the 1-hour tier. Pricing everything at 1.25x under-reports every one of them.

×6.7

Cache reads are 0.1x, not 0 and not 1

Ignore reads and you under-report by ~90%. Price them as input and you over-report by ~670%. Both mistakes have shipped in real tools this year; the fixes were merged by the author of this one.

Questions

I am on Claude Pro or Max. I do not pay per token. Why would I care?
Subscriptions do not bill per token, but the usage window drains in proportion to what the same requests would cost at API list price. billproof shows that number and says so plainly. When a window jumps from 20% to 90% in one turn, the receipt names the turn and the reason.
Does anything leave my machine?
No. The scan and the receipt read ~/.claude/projects locally and write nothing anywhere else. The only network call the tool ever makes is validating a license key when you run activate. The source is public so you can check.
How do you know the prices are right?
Every price row in the table cites the official pricing page and the date it was fetched. Every pricing rule and every root-cause rule is a unit test. Legacy models not on the current page are flagged price-unverified whenever they are used instead of being silently guessed.
Which tools does it read?
Claude Code transcripts today. OpenAI Codex and OpenCode logs are next. Reconciliation against the Anthropic and OpenAI cost APIs for organisations is on the roadmap.
